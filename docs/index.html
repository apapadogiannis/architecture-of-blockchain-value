Three kinds of blockchain

The paper sorts blockchains by what they can deliver. A capability is a distinct type of service that a blockchain reliably provides, such as transferring value or running smart contracts. The three kinds below are the three curves in the first chart.

Single-capability
One narrowly defined service. The capability set has a single element, typically peer-to-peer value transfer. Examples in the paper: Bitcoin, Litecoin, Monero.
Multi-capability
Several services inside one programmable environment. Smart contracts let payments, tokens, lending and other applications run side by side and call one another. The set is larger but bounded. Examples in the paper: Ethereum, Solana, Cardano.
Meta-capability
An open-ended market of services. The network hosts whole sub-networks (subnets, parachains, zones), each able to define new services, and lets them interoperate. Examples in the paper: Bittensor, Polkadot, Cosmos, Avalanche.

In the model the kinds differ in two ways: how many capabilities they have (K), and how strongly those capabilities reinforce one another (η). A single-capability chain has K = 1 and nothing to combine. The paper assumes a meta-capability chain has at least as many capabilities, and at least as much complementarity, as a multi-capability one.

1. More capabilities, and how strongly they reinforce one another

A blockchain delivers K capabilities. In this benchmark each one is worth the same on its own, and every pair adds a bonus of size η because the two can be used together. Value then grows with the number of pairs, which is why it curves upward.

V = φ u N(u) · [ K + η · K(K − 1) / 2 ]

Equation (14) of the paper.

What each term means
V
Network value. The total economic value of the blockchain: the sum of what its capabilities are worth, alone and in combination.
φ
Value per unit. What one user's use of one capability is worth. It sums up price, quality and scarcity in a single number, in currency or as an index.
u
User base. The number of users of the network. This benchmark assumes full adoption: every user uses every capability.
N(u)
Network-effect multiplier. How much more useful a capability becomes as its user base grows. It is a pure number: 1 means no network effect. Panel 3 shows three forms it can take.
φ u N(u)
Value of one capability on its own. Per-unit value, times users, times the network effect. Everything in the bracket is counted in units of this.
K
Number of capabilities. How many distinct services the blockchain delivers. A single-capability network has K = 1, for example value transfer only.
η
Complementarity. The extra value created when two capabilities are used together, as a fraction of one capability's value. With η = 0 the capabilities do not interact; with η = 0.5 every pair adds half a capability's worth.
K(K − 1) / 2
Number of pairs. How many different pairs can be formed from K capabilities: 1 pair for 2 capabilities, 45 for 10, 1,225 for 50.
η multi, η meta
The complementarity of each kind of chain. The sliders below set η separately for a multi-capability and a meta-capability chain. The paper's illustration uses 0.5 and 0.75.
[ … ]
The bracket. The first term, K, counts the capabilities themselves. The second, η K(K − 1)/2, counts the bonus from all pairs. The chart plots this bracket, that is, value with φ = u = N = 1, so that only the effect of capabilities and complementarity is visible.

A simplification to keep in mind. This benchmark gives every capability the same value. Panel 2 shows what changes when they are not equal. The curves are not a ranking of actual networks.

2. What if the capabilities are not equally valuable?

Then the network is worth less, and the reason is the bonus from pairs. The bonus that two capabilities create together is proportional to the product of their values, and a product is largest when the two are equal.

Two capabilities, 2 units of value in total
1 + 1
Bonus = η × 1 × 1 = η × 1.00. Equal split: the largest possible bonus.
1.5 + 0.5
Bonus = η × 1.5 × 0.5 = η × 0.75.
1.9 + 0.1
Bonus = η × 1.9 × 0.1 = η × 0.19. The total is still 2, but there is little to combine with.

3. How value grows with the number of users

In the equation of panel 1, the part u N(u) depends on how users connect. Three classical laws give three very different curves. The paper associates single-capability networks mainly with Metcalfe, multi-capability networks with a move from Metcalfe toward Reed, and meta-capability networks with Reed.

V(u) = u N(u)

One capability (K = 1) with φ = 1, so that only the effect of users is visible.

What each term means
u
Number of users of the network.
V(u)
Network value when the network has u users. Units are arbitrary; what matters is the shape of the curve.
Sarnoff: V = u
Value grows in step with users, so N(u) = 1. Each user adds the same amount, as in broadcasting, where users receive but do not connect to one another.
Metcalfe: V = u²
Value grows with the number of possible links between two users, so N(u) = u. Typical of peer-to-peer payments: each new user can transact with every existing one.
Reed: V = 2ᵘ
Value grows with the number of possible groups users can form, so N(u) = 2ᵘ / u. Each new user doubles the count. Typical of systems built for coalitions, such as subnets or application clusters.

What this is, and is not. The model is stylized. The values η = 0.5 and η = 0.75 used in the paper are illustrations, not estimates, and the units of users and value are arbitrary. Nothing on this page values a specific network or token.
